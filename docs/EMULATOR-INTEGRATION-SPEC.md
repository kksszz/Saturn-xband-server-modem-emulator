# エミュレーター統合・追加モジュール仕様（YMIR／Mednafen）

2026-10-11。対象は公開開発版v0.5.0を基準とするYMIR／Mednafen向けソース統合キットと、公開後のサービスendpoint名称整理です。
XBANDサーバー／モデムと対戦ケーブルの共通部分、各ホストの結線・保存・設定を記載します。
サーバーEXEに接続するだけで通常版エミュレーターへ機能が追加されるものではなく、基準ソースへの差分適用と再ビルドが必要です。

| ホスト | 対象ソース | 組み込み構成 |
| --- | --- | --- |
| YMIR | `9a237ea6642912ae0833f691809aa47dc27f908d` | 付属統合差分＋外部XBAND部品。対戦ケーブルのSCI／TCP／設定UIは統合差分に含む |
| Mednafen | 公式1.32.1 | 基礎XBAND差分＋専用アダプター。対戦ケーブルは基礎差分適用後の任意追加差分で結線する |

## 共通部分とホスト固有部分

| 責務 | 共通部分 | YMIR固有 | Mednafen固有 |
| --- | --- | --- | --- |
| モデム・通信 | レジスター、AT、UART、接続状態、Windows転送所有者 | SH-2バスハンドラーの接続 | A-bus分割前の要求幅1／2／4を受ける |
| 割り込み・時刻 | 状態管理の部品 | YMIRのバス・割り込み・フレームコールバック | SCU EXT0+12、クロック、フレームコールバック |
| 所有と呼び出し | MMIO内でソケットの応答を待たない | C++20のFrontendModem | C++20ランタイムをC ABIでC++11ホストへ接続 |
| フラッシュ保存 | Windows画像保存部品 | プロファイルのPersistentState | Mednafen NVRAMのxbf拡張子 |
| 有限サターンメディアカード | 13バイト、挿抜、読取異常、交換制御、原ゲームによる消費 | 起動設定から読込、起動時の自動作成・挿入なし | 新規プロファイルは左右別ID・100度数・挿入ON |
| 交換先の保持 | 既存サターンメディアカードと残数を上書きしない | 実行中・本体リセットで保持。再起動は起動設定へ戻る | 絶対パスをselection.jsonへ保存。欠落・破損時に補充しない |
| 正常帰還の互換観測 | ゲームの勝敗を切断だけから推定しない | Mednafen用帰還検出は追加しない | 対象チケットのUART帰還列とボードID読取を照合して終了 |
| 対戦ケーブル | 独立したマスター／スレーブSCI、YLS1 TCP、任意の4096サイクル同期 | 本体SCI・DMA・IRQ・実行予算・UI。既存YMIR差分を維持 | 共通SCI／TCP部品をC ABIでSH7095・DMA・IRQ・実行ループへ接続 |

サーバーの待機・マッチング・メール・結果・ポイント・度数精算・管理画面は共通です。各ホストのために料金やメール台帳を複製しません。固定のゲーム番号やGUI描画を共通部品へ持ち込まず、バス・IRQ・時計・保存場所・ループへの結線をアダプターに限定します。現状はソース統合であり、安定したDLL／プラグインABIではありません。

共通の画像保存は `components/xband/include/xband/windows_image_storage.hpp`。YMIRの旧ヘッダーは互換エイリアスです。Mednafenは開発環境内のYMIRチェックアウトへの絶対パスに依存しません。

## 管理制御とサターンメディアカード

ゲストのPPP／UARTとは別の内部管理接続で、モデム1・2の回線状態とサターンメディアカード操作を交換します。version1の通知はconfigured、inserted、units、save_failed、command_tokenを持ち、対応版ではread_fault、replace_supported、can_replace等を追加します。読取異常や保存失敗ではunitsをnullとして0と区別します。

挿抜要求はversion、token、inserted、読取異常要求はread_fault、交換要求はimage_pathを追加します。同一トークンを二度適用せず、エミュレーター所有スレッドで適用します。交換時は旧サターンメディアカードを保存し、挿入中ならOFFを経て新サターンメディアカードをONに戻します。YMIRは次の完了フレーム、Mednafenは要求時フレーム番号＋2で復帰します。取り外し中なら交換後もOFFです。電話線ON・通信中の交換を禁止しませんが、精算途中の交換はサターンメディアカード不一致・結果不明になり得ます。

サーバーUIは50／100／任意0～32767度数で新しい独立ファイルを作成し、OKで交換要求を出します。既存サターンメディアカードの直接編集・補充ではありません。コマンド`49`による度数消費はゲームDISC(ROM)が行い、サーバーがサターンメディアカードファイルを書き換えて代行しません。2秒を超える管理通知の欠落は未取得として扱います。

セーブステートでサターンメディアカード残数・外部通信を巻き戻しません。古い通信チケットを復元して再開したり、結果不明の消費を再送したりしません。Mednafenの待機・正常帰還観測はホスト固有の互換処理であり、MMIOへのゲスト要求と読み取り専用RAM観測を使用し、ゲームRAMへ書き込みません。無通信・メニュー経過時間だけによる終了ではありません。

## 起動・番号・初期値

標準の `start-server.ps1` は新規環境のみ、メール送信1通1度数・通常対戦3度数の消費を有効にします。途中リセットは両側各1、受信のみは無料です。EXE単体の設定なし初期値は無効です。保存済みの有効／無効、サターンメディアカード残数、精算・メール・ポイント台帳は保持します。

標準10ゲームの新規配点は勝者+1／敗者0。保存済み配点は保持し、過去対戦へ遡及加算しません。配点・新規サターンメディアカードは試験用のローカル方針で、当時の公式値・実サターンメディアカード認証を確定したものではありません。

XBAND宛て番号は **0120-717360**（数字のみでは0120717360）です。ゲームで設定する端末自身の電話番号、内部の仮想対戦ルーティング番号、ホストTCPポートとは別です。サーバーの標準ベースポートは58240、サービスはbase+side、対戦はbase+2+side、管理はbase+4+sideです。左右でプロファイルと登録電話番号を分けます。

## 取り込み手順と配布境界

現行ソースのサービスendpointは端末1が`service-0`、端末2が`service-1`です。両アダプターを更新する場合はサーバーも更新してください。更新サーバーは旧`pb3-0`／`pb3-1`を同じ端末の別名として受け付けるため、旧アダプターも接続できます。対戦の`peer-*`、管理の`call-*`、各TCPポートは変更しません。詳細は[サーバー／モデム仕様の互換説明](SERVER-MODEM-SPEC.md#サービスendpointの名称と旧版互換)を参照してください。

- [YMIR取り込み手順](YMIR-INTEGRATION-MANUAL.md)：固定基準コミットと付属差分を使用します。
- [Mednafen取り込み手順](MEDNAFEN-INTEGRATION-MANUAL.md)：公式1.32.1の7対象ファイルをハッシュ検査し、差分を適用してUCRT64でビルドします。C++11ホストへMSVCライブラリをリンクしません。起動スクリプトへEXE・DISC・日本BIOS・プロファイル・Subscriber・Sideを指定します。[キット概要](../integration/mednafen/README.md)も参照してください。
- [サーバー／モデム仕様](SERVER-MODEM-SPEC.md)、[UI操作](SERVER-UI-MANUAL.md)：共通サービスの採用仕様です。

ZIPには共通ソース・各アダプター・各ホストの差分／スクリプト・サーバーEXE・設定・文書を含めます。エミュレーター本体／EXE、BIOS、ゲーム、個人プロファイル・サターンメディアカード・履歴は含めません。既存ソースをreset・上書きせず、未変更の基準ソースを別途用意します。過去リリースを上書きしません。

## 対戦ケーブルのホスト別設定

対戦ケーブルはXBANDモデムとは独立した直接通信経路です。XBANDモデム機能とは同時使用できません。
サーバー・電話番号・サターンメディアカード・ポイント・サーバー台帳は使用しません。

| 項目 | YMIR | Mednafen |
| --- | --- | --- |
| 設定入口 | Serial Port設定UI、`general.LinkSynchronization` | `integration/mednafen/start-link-cable.ps1` |
| 通常の初期状態 | ケーブル未接続、同期OFF | ケーブルOFF。専用起動時はケーブルON・同期ON |
| 標準ポート | 32458、1～65535 | 32458、ランチャーとランタイムは1024～65535 |
| 接続モード | 同一PC自動接続、LANホスト／クライアントの設定 | 専用ランチャーは同一PC自動接続のみ |
| 同期変更 | 左右とも同じ設定で再起動 | 左右とも同じ`-Synchronize 1`または`0`で再起動 |
| リセット／状態ロード | 同期ONの時間軸不一致でセッションを無効化。ローカル自動接続は新規接続を試行 | 明示切断し、左右ともプロセスを再起動 |

別PC間のLAN接続は将来の検討事項です。通信形式の一致だけを異種ホスト間の実ゲーム対戦確認とはしません。
SCI・YLS1・DMA／IRQ・同期・保存状態の詳細は[両ホスト向け対戦ケーブル仕様](BATTLE-CABLE-SERIAL-SPEC.md)、
Mednafenの追加差分の適用・ビルド・起動は[任意追加手順](../integration/mednafen/LINK-CABLE.md)を参照してください。

## v0.5.0の検証範囲

2026-10-11のサーバー／共通CTestは60/60、YMIR本体Releaseビルドと標準・通信回帰は21/21、Mednafen XBANDアダプターは3/3が成功しました。検証用ZIPからサーバーを再ビルドし、Mednafenアダプター3/3・共通SCI3/3も通過しています。追加の旧YMIR通信形式比較を含む共通SCI試験は4/4です。Mednafen本体は公式ソースからのクリーンビルドとCLI起動・SCI本体結線診断を確認済みです。[リリース検証記録](RELEASE-VERIFICATION.md)、[YMIR記録](../integration/ymir/VERIFICATION.md)、[Mednafen記録](../integration/mednafen/VERIFICATION.md)に範囲を分けて記載します。

2026-10-11のMednafen試験構成で、通常対戦の両端末各3度数（100→97）、勝者+1／敗者0、再接続で二重計上なしをユーザー操作と画面で確認しました。その後、メール送信1通追加1度数・受信無料の試験完了をユーザーが報告しました。その後、ユーザーから通信ログ機能の確認完了が報告されました。同一PC上の独立2プロセスの結果であり、全タイトル・別PC・実サターンメディアカード・完全な物理モデム互換を保証しません。

Mednafen対戦ケーブルの利用者による実ゲーム確認は詳細検証記録を参照してください。共通TCP部品だけでなく、各本体のSCI・DMA・IRQ・実行同期・終了処理を結線する必要があります。公開後のサービスendpoint整理は現行ソースの更新であり、公開済みv0.5.0のタグと配布ZIPは変更しません。
