# XBANDサーバーUI操作マニュアル

2026年10月9日更新。v0.2.0を基にした現在のソース版のサーバー管理画面を対象にします。通常UIから手動の仮想カード消費試験を外した版の説明です。公開済みv0.2.0 ZIPには、その試験ボタンが残っています。

この画面では、通信状況の確認、メール配信、利用時間、対戦待ち時間、ポイントと度数を管理できます。ゲームの起動、プレイヤーの選択、対戦やメール接続の操作は、対応するセガサターンエミュレーター側で行います。管理画面からゲームを操作する機能はありません。

## 1 起動と終了

1. Windows配布ZIPを展開します。ソース版では先にサーバーをビルドしてください。
2. 展開先で `start-server.ps1` を実行します。
3. `XBAND Server | Communication Monitor` が開いたことを確認します。
4. 接続モジュールを組み込んだ対応エミュレーターを起動し、接続先をサーバーの設定に合わせます。

```powershell
./start-server.ps1
```

既定の接続先はローカルPCの `127.0.0.1`、ポートは58240〜58245です。別ポートを使う場合は、エミュレーター側の設定も合わせます。同じポートで複数のサーバーを起動できません。

設定画面の閉じるボタンは、その画面を閉じるだけです。サーバーを終了する場合は、先にゲーム側の通信を終了し、メインのCommunication Monitorを閉じます。終了・更新前には、後述する保存データのバックアップを行ってください。

## 2 メイン画面の見方

左右の `MODEM 1` と `MODEM 2` は、それぞれ端末1と端末2です。中央の `XBAND SERVER` は対戦回線の状態を示します。表示は約500ミリ秒ごとに更新されます。

| 表示 | 意味と確認事項 |
| --- | --- |
| SERVER ONLINE / SERVER OFFLINE | エミュレーター側モデムとサーバーの接続状態。ONLINEだけでは対戦やメールの成功を意味しません。 |
| Phone | ゲーム側から確認できた登録電話番号。固定のテスト番号は表示しません。電話番号は設定・宛先の検索に使い、本人認証を証明するものではありません。 |
| READY / WAITING | 対戦回線の待機状態。 |
| WAITING FOR OTHER GAME | 対戦申し込みがあり、相手側の準備を待っている状態。 |
| INCOMING CALL / PEER RELAY ACTIVE | 対戦回線の接続処理中／中継中。勝敗確定の表示ではありません。 |
| SESSION CLOSED / Peer session disconnected | 対戦回線が終了または切断された状態。理由は履歴で確認します。 |
| Service UP / DOWN | ゲーム側からサーバーへ／サーバーからゲーム側へ流れたサービス通信のバイト数。 |
| 1 → 2 / 2 → 1 | 対戦回線の方向別通信量。DATAは直近に通信あり、IDLEは直近に通信がない状態です。 |
| accepted / delivered / queued | 中継に受け付けた量／相手側へ渡した量／差分。ゲーム側で処理完了した証明ではありません。 |
| Recent game bytes | 直近の通信をHEXと文字表示で確認する欄。ゲームの操作内容を解読した表示ではありません。 |
| Card: unknown (not reported) | この表示欄ではカード残度数を確認できません。ゲームの使用状況画面と精算履歴を確認してください。 |

メール関連のカウンターも、返信準備や保存の状況です。「保存済み」「応答へ格納」は、ゲーム側の受信完了・既読を意味しません。

### 画面上部のボタン

| ボタン | 操作できること |
| --- | --- |
| Mail history... | プレイヤーメールの履歴確認、お知らせメールの作成画面への移動。 |
| 接続・対戦・ポイント履歴... | 接続、マッチング、ポイント、度数精算の履歴確認。 |
| 使用状況の表示設定... | 電話番号ごとの対戦エリア表示、プレー時間表示、実際の時間帯制限。 |
| 対戦待ち時間設定... | 全端末共通の「みじかい／ふつう／ながい」の時間設定。 |
| Game / point settings... | ゲーム名、勝者・敗者ポイント、ゲーム追加、昇格条件の設定。 |
| 消費度数設定... | 全タイトル共通のメール・通常対戦の度数と、自動消費の有効化。 |

旧版では消費度数ボタンに「未有効」などの旧表記が残る場合があります。動作の有効・無効は、設定画面のチェック項目と保存状態で確認します。

## 3 メール履歴の確認

1. `Mail history...` を押します。
2. 一覧で日時、送信者、ユーザー枠、宛先、件名、状態を確認します。
3. 行を選択すると、下部に詳細を表示します。
4. `Previous`、`Next` でページを移動し、`Refresh` で最新の情報を読み直します。1ページは20件です。
5. `解析データ切替` は、選択したメールの詳細を通常表示と解析用表示で切り替えます。

「送信待ち」は、サーバーに保存され、応答へまだ格納していない状態です。「応答へ格納（受信未確認）」は、ゲーム側への返信に含めた状態で、配達・既読の確認ではありません。同じメールをゲーム側が再投稿した場合は、別の受付履歴として記録します。

この画面は履歴の確認用です。プレイヤーのメール本文を編集したり、削除・再送したりする操作はありません。お知らせメールを作成する場合は `センター配信メール...` を押します。

## 4 お知らせメールの作成と登録

開き方は `Mail history...` → `センター配信メール...` です。差出人はXBAND、住所表示は東京で、アイコンにはゲームDISC(ROM)内のXBANDリソースを使います。

1. 配信先を選びます。

   - `全ユーザー`：今後接続するユーザーも含む全体向けです。
   - `電話番号・ユーザー枠を指定`：登録電話番号を入力し、その端末の全4枠または枠1〜4を選びます。

2. 件名と本文を入力します。
3. 配信先・文面を確認して `配信キューへ登録` を押します。
4. 確認画面で「はい」を選びます。
5. 「配信ID … を保存しました」と表示されたことを確認します。

件名は32バイト、本文は240バイト以内です。文字コードはEUC-JPで、日本語は通常1文字2バイトです。件名32文字・本文240文字まで使えるという意味ではありません。絵文字など対応しない文字は登録できません。

登録したメールは、対象ユーザーの次回接続時に返信へ含めます。接続中のゲームへ即座に表示する機能ではありません。受信箱が満杯のときはサーバーに残します。返信へ格納した後は自動再送しません。

`サンプルメール作成` は件名・本文に例文を入力するだけで、登録・配信は行いません。入力中の文面がある場合は置き換え確認が出ます。例文の障害案内は現在のサーバー状態を表すものではないため、内容を必ず修正・確認してください。

下部の履歴は `履歴を更新` で更新します。行を選ぶと本文を確認できます。「応答格納ユーザー数」は、返信を準備した対象数で、実際の受信者数・既読者数ではありません。登録後の配信を取り消すボタンや編集ボタンはありません。誤登録を防ぐため、確認画面で宛先と文面を見直してください。

## 5 接続と対戦の履歴確認

1. `接続・対戦・ポイント履歴...` を押します。
2. 最新の履歴から、対象端末・ユーザー・ゲーム・イベントを確認します。
3. 行を選び、下部の詳細で接続履歴ID、勝敗報告、加算額、度数などを確認します。
4. `前へ`、`次へ` で移動し、`更新` で読み直します。1ページ50件で、約1秒ごとに更新されます。横に隠れた列は横スクロールで確認します。

| 主なイベント | 意味 |
| --- | --- |
| アクセス受付、待機登録、マッチング成立 | サービス要求と相手探しの進行。 |
| 対戦回線接続、対戦回線切断 | 回線の状態。これだけでゲームの正常終了や勝敗は確定しません。 |
| 対戦結果・加算算出、ポイント台帳記録 | 結果に基づくポイント算出・サーバー側の保存。ゲーム画面への反映とは別です。 |
| 結果再報告・加算なし | 重複報告として追加のポイント加算を行っていない状態。 |
| 度数精算・確定 | 消費実績とカード更新を確認して精算を記録した状態。 |
| 度数精算・結果不明、度数精算・処理停止 | 安全のため新しい自動消費を停止している状態。再接続での二重消費を避けます。 |
| 度数精算・残高不足の部分消費 | 要求全額には足りないものの、残度数を使い切った実績を確認した状態。 |
| 時間帯制限・接続拒否、時間帯制限・待機終了 | 保存済みの利用時間条件による拒否・待機終了。 |

過去の履歴には、現在の通常UIにはない手動度数試験の記録が残る場合があります。過去の記録を削除・再実行するための画面ではありません。

### 対戦結果DB

履歴画面の `対戦結果DB...` から開きます。端末が報告した結果、報告ユーザー、エラー値、照合先、実加算と累積ポイントを確認できます。行を選ぶと、下部に保存データをJSONで表示します。

左右の報告は別の行で保存します。片側しか報告していない場合や、解明できていない項目は、サーバーが推測して確定しません。この画面から結果の修正・ポイント再加算・記録削除はできません。

## 6 使用状況の表示と時間帯制限

開き方は `使用状況の表示設定...` です。最初に、対象端末がゲーム側に登録している電話番号を選択または入力します。同じ電話番号の端末の4ユーザー・全ゲームに共通の設定です。電話番号は検索キーで、認証済みIDではありません。

### 対戦エリアの表示

次のいずれかを選び、`保存` を押します。

- `上書きしない（保存済みの設定は戻りません）`：ゲーム側のエリア表示を上書きしません。以前にゲーム側へ保存された値を元へ戻す操作ではありません。
- `同一局番内に固定（操作不可）`：ゲーム側のエリア表示・選択を固定します。
- `全国に固定（操作不可）`：ゲーム側のエリア表示・選択を固定します。
- `ゲームDISC(ROM)で任意選択（同一局番内／全国）`：ゲーム側での選択を許可します。

地域に基づいて実際の対戦相手を絞り込む処理は未実装です。この設定を「地域別マッチング」の有効化として扱わないでください。

### プレー時間の表示だけを変更する

時間帯制限のチェックを外した状態で、表示方法を選びます。

1. `時間制限なし（1行）` または `サーバー指定（2行・任意の文言）` を選びます。
2. 2行指定の場合は上段・下段を入力します。各行30バイト以内のEUC-JP文字列です。
3. `保存` を押し、保存メッセージを確認します。

`動画と同じ表示` は「月－金 利用可能」「土－日 利用可能」の例文を入力するボタンです。押しただけでは保存されません。表示文に利用時間を書いても、それだけで接続は制限されません。

### 実際に接続できる時間を制限する

1. `時間帯制限を有効にする` をチェックします。
2. `対戦接続のみ制限（メール利用可能）` または `対戦とメールの接続を制限` を選びます。
3. 月〜金と土・日をそれぞれ設定します。`終日利用可能`、`時間帯を指定`、`利用不可` から選びます。
4. 時間帯指定の場合は開始・終了時刻を `HH:MM` で選択または入力します。
5. `保存` を押します。

時刻は日本時間です。1分単位の手入力ができ、開始は00:00〜23:59、終了は24:00も指定できます。終了時刻ちょうどは利用可能時間に含みません。開始と終了が同じ場合は保存できません。終日許可には `終日利用可能` を使います。

例として平日18:00〜22:00、土・日を終日利用可能にすると、平日は18:00から22:00直前まで利用できます。22:00〜02:00のような設定は、開始日の翌日02:00までです。金曜夜から土曜、日曜夜から月曜にまたがる分も、開始日の設定を引き継ぎます。

制限は保存直後から適用されますが、すでに接続している対戦は途中で切断しません。制限を有効にするとプレー時間表示は曜日別条件から自動生成されます。ゲーム側の表示は次の対戦接続後、使用状況を開き直して確認します。制限を解除する場合はチェックを外して保存します。

## 7 対戦待ち時間の設定

1. `対戦待ち時間設定...` を押します。
2. `みじかい`、`ふつう`、`ながい` をそれぞれ1〜60分から選びます。
3. `みじかい ≦ ふつう ≦ ながい` の順になっていることを確認します。同じ値でも保存できます。
4. `保存` を押し、保存済みの値を確認します。

初期値は1分・2分・4分です。`初期値を表示` は入力欄を初期値に戻すだけで、適用には `保存` が必要です。

全電話番号・全ユーザー・全タイトルに共通で、保存後の新しい申し込みから適用します。すでに待機中の期限は変わりません。ゲーム側へ出す案内文と実際の待機期限に同じ値を使います。

## 8 ゲーム名と勝敗ポイントの設定

開き方は `Game / point settings...` です。ここで設定するポイントは、カードの残度数とは別です。

1. `Game / fixed ID` で対象ゲームを選びます。
2. 表示名を変える場合は `Game name` を編集します。
3. `Match award` で `Use server-configured award` を選びます。
4. 勝者ポイントと敗者ポイントをそれぞれ0〜999で指定します。
5. `Save` を押します。

`No server override` を選ぶと、サーバーによる両者のポイント加算を行いません。引き分けの加算は0です。設定はゲーム別ですが、同じゲームの全電話番号・4ユーザーに共通です。変更後の新しい対戦から使い、すでに保存されている累積ポイントを変更しません。結果報告後の接続で累積ポイントをゲーム側へ配信します。

`Current level`、`Current points`、`Next level`、`Points still required` は直接編集できません。この画面で個々のユーザーの残高やポイントを手動補充することはできません。

`Reset title / award` は選択ゲームの表示名・配点の初期値を入力欄に表示します。適用には `Save` が必要で、累積ポイントを消去する操作ではありません。`Close` は設定画面を閉じます。

### ゲームを追加する

1. `新規ゲームID (HEX)` に、実際のゲーム通信で確認したIDを16進数で入力します。`0x` は付けても省略しても構いません。
2. `新規ゲーム名` を入力します。
3. `ゲームを追加` を押し、保存メッセージを確認します。このボタンで保存まで行います。

IDは1〜8桁で、0とFFFFFFFF、重複IDは使えません。標準ゲームを含め最大63ゲームです。追加時のポイントは勝者1・敗者0、ランクはLEVEL表示・200ポイント刻みです。追加後に変更できます。

ゲームをリストへ追加しても、未対応のゲームが自動的に通信対応するわけではありません。度数処理や料金はゲーム別には変更されず、全タイトル共通のままです。

## 9 昇格条件とランク表示の設定

`Game / point settings...` → `昇格条件...` から開きます。

### 個別のランクを変更する

1. 対象ゲームとランクを選びます。
2. そのランクに到達する累積ポイントを入力します。
3. `このランクを保存` を押します。

30ランクあり、最初のランクは0固定です。以降の到達ポイントは、前のランクより大きく、次のランクより小さくなるよう設定します。上限は999999999です。同じポイントに複数のランクを設定できません。

### 全ランクを等間隔にする

`全30ランクの間隔` に値を入力し、`選択ゲームに一括適用` を押します。選択したゲームの全30ランクをその間隔で保存し直すため、個別に調整した値も置き換わります。他のゲームは変更しません。

初期値200では、第1ランクは0、第2ランクは200、第30ランクは5800です。間隔は1〜34482758で指定できます。この初期値は、当時の公式昇格条件の復元ではありません。

### 表示形式を変更する

`表示単位` でLEVEL・段・級を選び、数字の順序を昇順または降順にして `表示形式を保存` を押します。降順でも、累積ポイントに応じて進む内部ランクの順序は変わりません。例えば級を降順にすると、最初の表示は30級になります。

昇格条件は次のサーバー接続で既存の累積ポイントから再計算します。表示形式の保存と、到達ポイントの保存は別のボタンです。最大ランクでは次の昇格はありません。

## 10 消費度数の設定

開き方は `消費度数設定...` です。これは仮想カードに残っている度数を消費する設定で、実際のお金を請求する機能ではありません。料金と処理は全電話番号・4ユーザー・全タイトルで共通です。

1. `メールアクセス時の消費要求` に1、`通常対戦の度数（次の接続で精算）` に3を入力します。これが標準の料金です。
2. メール分を消費する場合は `メール接続の自動消費を有効にする` をチェックします。
3. 対戦分を精算する場合は `新しい対戦の自動精算を有効にする` をチェックします。
4. `設定を保存` を押します。

初期状態では両チェックとも無効です。数値を入力しただけでは自動消費を有効にしません。0〜32767の整数を指定できますが、これはローカル実装の上限で、当時の料金上限を示すものではありません。

途中リセットの対戦分は、両側とも各1度数固定です。通常対戦分3に1を追加するのではなく、対戦分を1に置き換えます。リセットした側がどちらかを責任判定して料金を変えることはありません。

両チェックを有効にし、メール1・通常対戦3にした場合の消費は次のとおりです。

| 利用 | 各端末の消費度数 |
| --- | --- |
| メール接続のみ | 1 |
| 通常対戦後のメール接続 | 対戦3＋メール1＝4 |
| 途中リセット後のメール接続 | 対戦1＋メール1＝2 |

対戦分は、各端末が次に新しい結果を添えて接続した際に個別精算します。相手の接続を待ちません。設定の変更は新しい接続・対戦へ適用し、旧履歴をさかのぼって自動請求しません。自動消費を止める場合は対象のチェックを外して保存します。チェックを外すことは、過去の消費や精算記録の取消ではありません。

残度数が不足した場合は対戦分を優先し、メール分が足りなければメールを進めません。要求より少ない残度数を使い切った場合も、負の残度数を保存するのではなく、部分消費を確認して終了します。

返信欠落、タイムアウト、カードの不一致などで結果が不明な場合は、新しい自動消費を止めます。未分類のエラーや強制終了を、すべて途中リセット1度数として扱うわけではありません。結果不明の同じ要求を自動再送したり、度数を補充・返還したりはしません。画面に「未確認」「結果不明」が出たら、カードと履歴を保全して確認してください。

仮想カードは対応エミュレーター側で指定します。サーバーUIには、カードの作成、挿入、残度数の直接編集、補充の操作はありません。通常UIから手動の消費試験を開く機能もありません。

## 11 保存場所とバックアップ

`start-server.ps1` で起動した場合、展開先の `runtime` に保存します。別の起動方法や環境変数を使う場合は保存先が変わるため、以下は標準起動時の配置です。

| 保存先 | 内容 |
| --- | --- |
| activity-history | 接続・マッチング・ポイント・精算の観測履歴。 |
| mail-journal | メール、配信登録、返信への格納状態。 |
| game-result-db | 端末から報告された対戦結果。 |
| game-ranking-settings.json | ゲーム一覧・表示名・勝者／敗者ポイント。 |
| game-point-ledger.json | ユーザー別の累積ポイント。 |
| game-level-settings.json | ゲーム別の昇格条件・表示形式。 |
| usage-area-settings.json | 電話番号別のエリア表示・プレー時間・時間帯制限。 |
| standby-wait-settings.json | 共通の対戦待ち時間。 |
| service-credit-settings.json | 共通料金・自動消費の有効／無効。 |
| service-credit-settlements.json | 消費要求と実績・精算状態。 |
| match-credit-episodes.json | 精算対象となる対戦の記録。 |

バックアップは、ゲーム通信を終了しサーバーを停止してから、`runtime` 全体と、エミュレーター側で使用中の仮想カードファイルをまとめて保全します。カードだけを古い状態に戻したり、精算台帳だけを削除したりすると、保存内容の不一致を起こすおそれがあります。

設定画面を閉じるだけでは、入力中の値は保存されません。保存ボタンを押し、成功メッセージを確認してください。保存失敗や不正な設定ファイルのエラーが出た場合は、ファイルを削除してやり直さず、そのまま保全して原因を確認します。

## 12 困ったときの確認順

| 状況 | 確認すること |
| --- | --- |
| メイン画面が開かない | 実行ファイルの存在、別サーバーとのポート競合、起動したPowerShellのエラー。 |
| モデムがOFFLINE | 対応エミュレーターの接続モジュール、接続先・ポート。通常のエミュレーターを起動するだけでは接続できません。 |
| 「接続成功」の後に停止・エラー | 接続・対戦履歴で、その時刻のサービス中断・エラー・度数停止・時間帯拒否を確認。ONLINE表示だけで正常完了と判断しません。 |
| メールが見えない | 配信先の電話番号と枠、次回接続、受信箱容量、時間帯制限、残度数、メール履歴の状態。 |
| 設定がゲーム画面に出ない | 保存成功を確認し、対応する次回接続を行って画面を開き直す。接続済みの画面へ即時プッシュはしません。 |
| ポイントが増えない | 対戦時の配点設定、結果報告、重複報告、引き分け、台帳記録を確認。配点保存だけで既存累積は増えません。 |
| 度数が減らない | 有効化のチェックと保存、カード挿入、結果付き接続、精算履歴。ゲームの表示を開き直して確認。 |
| 度数の結果が不明 | 同じ消費を再予約・再送せず、カードと精算履歴を保全。成功したと推測して補充・返還しません。 |

内部コマンドやカード形式の詳細は[統合仕様書](SERVER-MODEM-SPEC.md)、リリース内容は[README](../README.md)を参照してください。
