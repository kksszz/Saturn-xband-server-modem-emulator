# 単体サーバー用の設定ファイル（開発中）

更新日：2026-09-27

今回追加したEXEは **設定の検査専用** です。サーバーの待受・ゲームの起動・
設定の保存は行いません。既存のモデム監視EXEを置き換えるものではありません。

## 検査方法

```powershell
.\build\Release\xband_config_check.exe .\tests\fixtures\server-config.json
```

この例は components/xband を作業ディレクトリとした場合です。
成功時は終了コード0、不正な設定や読み取りエラーは1、引数不足は2です。
共有キーや設定ファイルの内容は表示しません。

## フィールド

| 項目 | 内容 |
|---|---|
| version | 必須。設定形式の番号。現在は整数1 |
| port | 必須。将来の待受ポート。整数1～65535 |
| bind_address | 省略時は127.0.0.1（このPCだけ）。IPv4の数値表記 |
| allow_lan | 省略時はfalse。LAN用アドレスを指定するときだけtrue |
| identities | 必須。接続を許可する端点の配列。1～32件 |
| identities内のendpoint | 1～32文字の英数字・ハイフン・アンダースコア。重複不可 |
| identities内のauth_key | 64文字の小文字16進数。クライアント側と一致させる専用キー |

不明な項目、JSONキーの重複、ポートの文字列表記、形式不正の共有キーは拒否します。
設定サイズの上限は64KiBです。TLSの設定項目はありません。通信は承認済み方針どおり平文TCPです。

## LAN利用時の制限

現在の検査は、ループバックか、明示的に許可されたプライベートIPv4
（10.x、172.16～31.x、192.168.x）の形式かを確認します。
0.0.0.0、ホスト名、IPv6、公開IPなどは受け付けません。
設定検査EXEだけでは、そのIPが実際にこのPCへ割り当てられているかは確認しません。
新しいWindows待受部品は、待受前に稼働中インターフェースのユニキャストアドレスと
照合します。ループバックの特例は127.0.0.1のみです。設定検査に合格しても、
実際の待受時には未割当アドレス・使用中ポート等で失敗する場合があります。
ファイアウォールを自動で変更する予定はありません。

この待受部品は現在、テストEXEから呼び出して検証しています。設定検査EXE自体は
引き続き通信を開始しません。既存の監視UIやゲーム用EXEへの組み込みは未実施です。

## 診断用サーバーEXE

別途 `xband_diagnostic_server.exe` を追加しました。こちらは診断用の通信処理を
実際に待ち受けます。ただし、ゲーム用サーバーの完成版ではありません。

```powershell
.\build\Release\xband_diagnostic_server.exe .\tests\fixtures\server-config.json 30000 --ephemeral-loopback
```

components/xband を作業ディレクトリにして実行する例です。30秒で自動終了します。
時間は1～60000ミリ秒を必須指定し、Ctrl+Cでも停止できます。
`--ephemeral-loopback` 指定時はOSが空いているポートを選び、起動時に表示します。
省略すると設定ファイルのポートを使います。127.0.0.1以外、またはallow_lan=trueの
設定は、この診断用EXEでは拒否します。Windowsサービス登録・自動起動はしません。

このEXEが扱うのは既存の限定的な診断用PPP処理です。試験用のclock_hz=1000、
1000tickで1診断フレームという条件に固定しており、実際のYmirのクロックとは異なります。
現行のゲーム用ランチャーの接続先として使わないでください。画面やカード管理UIはありません。
通常のゲーム動作確認をユーザーへお願いする段階ではありません。

開発用ビルドで、JSON対応・Windows・既存診断ヘッダーのパス・BUILD_TESTINGが
有効な場合に作成されます。試験終了時には接続と待受ソケットを解放します。

## テスト用設定との区別

診断クライアントは、無通信が2秒続くと届くpingに対して、対応するreply_toを
指定したpongを返す必要があります。pingの送信キュー登録から5秒以内に返信が
なければ切断します。別の状態通知を送っても、この応答期限は延長しません。
snapshotで受け取ったカード残高などは表示用情報であり、残高を書き換える処理では
ありません。状態情報のUIへの反映はまだ未実装です。

tests/fixtures/server-config.json のポート58133と、aを64個並べたキーは試験用です。
本番設定として導入・保存していません。実運用時は専用キーを用意してください。
共有キーも通信内容も暗号化されません。アカウントのパスワードを流用しないでください。

エミュレーターのクロック設定・モデムの電話番号・カード残高は今回のファイルに含めません。
特にカード残高をサーバー設定へ移す変更ではありません。
